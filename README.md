# WellTempProfile — 注气井温度剖面显示

Qt 5.12 / C++ 客户端控件：把每 2 秒上传一次的整条井筒温度数据，实时显示成
**井深 × 时间 × 温度** 的 3D 曲面图（或 2D 热力图），带色带、交互缩放、点选读数和导出。

---

## 1. 环境与编译

| 项目 | 要求 |
|---|---|
| Qt | 5.12（C++11） |
| 模块 | `core gui widgets datavisualization concurrent` |
| 构建 | qmake，打开 `WellTempProfile.pro` 即可 |
| 编译器 | MSVC 需要 `/utf-8`（`.pro` 已配置），源码为 UTF-8 |

注意：
- `Qt Data Visualization` 是附加模块，Qt 安装器里需要勾选；开源版为 GPLv3，商业项目请确认授权。
- 3D 视图依赖 OpenGL 2.1+。没有独立显卡但有集成显卡一般没问题；若机器没有任何显卡驱动（如部分 Windows 工控机），
  需要部署 Qt 自带的软件 OpenGL（`opengl32sw.dll`）或设置环境变量 `QT_OPENGL=software`。
  **2D 热力图为纯 CPU 绘制，不依赖 OpenGL。**

---

## 2. 快速开始

1. 用 Qt Creator 打开 `WellTempProfile.pro`，选 Qt 5.12 的 Kit，编译运行。
2. 默认启用了模拟数据（`.pro` 里的 `DEFINES += USE_SIMULATOR`），启动后即可看到类似参考图的温度剖面。
3. 接入真实数据：见第 4 节。接入时**必须注释掉 `DEFINES += USE_SIMULATOR`**，否则模拟器和真实数据会同时写入缓冲。

调试加速：`MainWindow.cpp` 里 `sim_->start(2000, 2000)` 改成 `sim_->start(200, 2000)`，即 10 倍速。

---

## 3. 整体结构

```
 设备/网络层
     │  pushFrameMs(温度数组, 时间戳, 点间隔)
     ▼
 DataIngest ──校验/清洗──► FrameBuffer（环形缓冲，只保留最近一段时间的原始帧）
                                │
                                │  Resampler（工作线程）：降采样成固定大小的显示网格
                                ▼
                              Grid（rows × cols）
                                │
              ┌─────────────────┴─────────────────┐
              ▼                                   ▼
        SurfaceView (3D)                    HeatmapView (2D)      ← 都继承 ProfileView
              └─────────────── MainWindow ────────┘
                    （控制栏、范围缩放、冻结/跟随、导出、设置）
```

核心思路：**原始数据和显示网格分开**。每帧最多几万个点、按小时累积是上亿个点，不能直接喂给曲面图；
所以原始帧只放在缓冲里，显示时按需降采样成约 15 万个顶点以内的网格。

### 文件说明

| 文件 | 作用 |
|---|---|
| `Config.h` | `DepthInfo`（深度结构）、`ViewConfig`（全部可配置项）、枚举 |
| `DataIngest` | **真实数据入口**，线程安全；校验、清洗无效点、自动确定深度结构 |
| `FrameBuffer` | 线程安全环形缓冲，按时间保留原始帧，内存占用恒定 |
| `Resampler` | 降采样：时间箱对齐绝对时间网格，窗口滚动时画面不抖 |
| `ProfileView` | 3D/2D 视图的公共接口 |
| `SurfaceView` | 3D 曲面（Qt Data Visualization）+ 色带 + 滚轮缩放范围 |
| `HeatmapView` | 2D 热力图（纯 QPainter），悬停读数、点选 |
| `ColorBar` / `ColorMap.h` | 色带控件；jet 色阶与刻度算法（3D、2D 共用） |
| `TimeAxisFormatter` | 3D 时间轴 `HH:mm:ss` 标签 |
| `SettingsDialog` / `ConfigStore` | 设置面板；配置保存到用户 INI 文件（UTF-8） |
| `DataExporter` | CSV 导出（UTF-8 带 BOM，Excel 直接打开） |
| `DataSimulator` | 研发阶段的模拟数据，接入真实数据后可整体删除 |
| `MainWindow` | 主窗口与全部调度逻辑 |

## 4. 接入真实数据

数据到达处调用：

```cpp
// 时间戳为毫秒（自 1970-01-01 UTC）
w.ingest()->pushFrameMs(m_temperData, tsMs, spatialResolution);

// 时间戳为 QDateTime
w.ingest()->pushFrame(m_temperData, dateTime, spatialResolution);
```

- `m_temperData`：`QVector<float>`，一个时刻整条井筒的温度，下标 0 对应起始井深。
- `spatialResolution`：相邻两点的间隔，**单位米**。
- 线程安全，可以直接在设备/网络线程调用。返回 `true` 表示该帧被接收。

`DataIngest` 会自动处理：

- **深度结构**：第一帧到达时用数组长度作点数、`spatialResolution` 作点间隔，重置缓冲并把查看范围设为整段井深。
  点数、点间隔或起始井深变化时同样会重置（**旧数据被清空**）。
- **无效点**：非数值或超出有效范围（默认 −100 ~ 300 ℃，可用 `setValidRange()` 修改）的点，
  用同一帧里前一个有效值填充；整帧无效则丢弃。
- **坏帧丢弃**：数组为空、点间隔非正、时间戳无效、时间戳没有比上一帧大（重复/乱序）。
  日志里会有警告（前 5 次，之后每 100 次一次），`acceptedCount()` / `rejectedCount()` 可查累计数。

**起始井深**：数据里没有“第 0 个点对应的井深”，需要在设置面板“起始井深”里填写（默认 0 m）。
修改后下一帧到达时会清空缓存并重建。

时间显示使用本机时区；若用设备时间戳，设备时钟与本机不一致时，时间轴显示的是设备时间。

## 5. 界面与操作

### 控制栏

| 控件 | 说明 |
|---|---|
| 视图 | 3D 曲面 / 2D 热力图切换（只有当前可见的视图收到新数据） |
| 时间窗口(秒) | 显示“最近 N 秒”，手动修改即回到滚动模式 |
| 跟随最新 | 选中：右端跟随最新数据；取消：冻结当前时间范围 |
| 井深 min ~ max | 精确输入查看的井深范围，回车生效；“重置深度”恢复整段井深 |
| 显示色带 | 显示/隐藏右侧色带 |
| 设置… | 打开设置面板 |
| 导出图片 / 导出数据 | 见第 7 节 |

### 鼠标

| 操作 | 3D 曲面 | 2D 热力图 |
|---|---|---|
| 旋转 | 左键拖动 | — |
| 缩放视角 | 滚轮 | — |
| 点选读数 | 左键点击 | 悬停即显示；左键点选并标记，右键取消 |
| 缩放**井深范围** | Shift + 滚轮 | Shift + 滚轮 |
| 缩放**时间范围** | Ctrl + 滚轮 | Ctrl + 滚轮 |
| 缩放中心 | 最近点选的点（没有则取范围中点） | 鼠标位置 |

范围缩放后，降采样会从原始数据重新计算，放大看到的是真实细节，而不是把粗网格拉大。
井深缩放到几百米以内时是 0.4 m 的原始分辨率。

### 跟随 / 冻结

- 在跟随模式下把时间范围缩小，会自动**冻结**在该范围；
- 冻结时把右端拉回到最新数据，会自动回到**跟随**，窗口长度取当前跨度；
- 冻结期间内存会多保留一些数据，上限见下文 `maxRetainSec`。

要移动查看范围：井深用输入框；时间取消“跟随最新”后用 Ctrl+滚轮缩放。（没有平移功能。）

## 6. 配置

设置面板（“设置…”）可改：

- 标题、井深/温度/时间轴名称、时间显示格式（Qt 格式，如 `HH:mm:ss`）
- 起始井深、时间窗口、刷新周期、网格最大行/列数、降采样聚合方式（平均/最大/最小）
- 温度范围（自动/固定）、是否显示色带

“应用”立即生效，“确定”应用并关闭，“恢复默认”只重置面板上的值。
配置保存为 UTF-8 的 INI 文件（`QSettings`，组织名 `WellTempProfile`，文件名 `settings`），下次启动自动恢复。
当前井深/时间的查看范围属于视图状态，不保存。

只能在 `Config.h` 的 `ViewConfig` 里改（面板里没有、也不保存）的项：

| 字段 | 默认 | 含义 |
|---|---|---|
| `retainSec` | 1800 | 内存中至少保留的原始帧时长（秒） |
| `maxRetainSec` | 7200 | 保留时长上限（冻结/放大时间范围时受此限制） |

内存估算：每帧 `点数 × 4 字节`，5 km（12500 点）约 50 KB/帧；7200 s 约 3600 帧 ≈ 180 MB。

### 性能参考

3D 曲面每个网格点是一个顶点。无独显时建议 **行数 × 列数 ≤ 30 万**（默认 300 × 700 = 21 万）。
设置面板会在超过时给出提示。2D 热力图不受这个限制。

## 7. 导出

- **导出图片**：PNG / JPG。按 1.5 倍窗口尺寸、4 倍 MSAA 渲染，上方带标题和时间/深度范围，色带显示时一并导出。
  无独显或软件渲染下若失败或很慢，可在 `MainWindow::exportImage()` 里调低倍数和 MSAA。
- **导出数据 → 当前显示网格**：屏幕上看到的降采样结果。首行为井深，首列为时间。
- **导出数据 → 当前范围原始数据**：当前时间/井深范围内的全分辨率数据。
  只能导出缓冲里还保留着的部分。

CSV 均为 UTF-8 带 BOM，导出在后台线程进行，不卡界面。

## 8. 已知限制

- 深度结构（点数/点间隔/起始井深）变化时会清空缓冲，不支持同一缓冲里混合不同结构。
- 暂无历史回放。`FrameBuffer` 只保留近期数据；需要回放时，可新增“从文件/数据库读取”的数据源，
  Resampler 和显示层不用改。
- 点选高亮：3D 视图在数据刷新后会清除高亮（行列下标对应的数据已经变了），读数文字保留；2D 视图的标记按深度/时间定位，会随数据滚动移动。
- 3D 视图是嵌入的 OpenGL 窗口，在个别环境下切换视图/隐藏再显示可能出现闪烁或黑屏。

## 9. 常见问题

| 现象 | 可能原因 |
|---|---|
| 中文乱码 | 源码需 UTF-8；MSVC 需 `/utf-8`；项目里中文字符串统一使用 `QObject::tr()` |
| 一直显示“等待数据…” | 还没有数据；或帧长度与深度结构不一致被丢弃（看日志里 `DataIngest` 的警告） |
| 3D 视图空白/无法启动 | OpenGL 环境不满足，参考第 1 节；可先切到 2D 热力图 |
| 图上井深刻度不对 | 起始井深未填，或 `spatialResolution` 单位不是米 |
| 图上出现很深的沟 | 无效值标记不在默认有效范围内，用 `setValidRange()` 调整 |
| 模拟数据和真实数据混在一起 | 忘了注释 `DEFINES += USE_SIMULATOR` |

## 10. 迁移到 Qt 6 时需要注意

- `Qt Data Visualization` 在 Qt 6 中是独立的附加模块，需要单独安装；`.pro` 改 `QT += datavisualization` 仍可用，CMake 用 `Qt6::DataVisualization`。
- `QSettings::setIniCodec` 在 Qt 6 中已移除（默认即 UTF-8），`ConfigStore.cpp` 里的 `open()` 需删掉。
- `QWheelEvent::pos()` 在新版本中已废弃，建议改用 `position().toPoint()`。
- `QtConcurrent::run` 的函数指针写法在 Qt 6 仍可用，但参数传递语义有细微差异，升级后需要回归测试。
- `QOverload<>::of` 可改为 `qOverload<>()`（需要 C++14）。
